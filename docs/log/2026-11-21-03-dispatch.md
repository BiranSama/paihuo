# 私聊与工作项可以在内核里并行调度

- 日期：2026-11-21
- 谁：T-008 工人 / Astra / Codex
- 关联：[T-008](../../tasks/T-008.md) · [PR #15](https://github.com/BiranSama/paihuo/pull/15) · Q-011、Q-014、Q-015

## 实现与接入

每次开库创建一个 `createDispatch(store, registry, options?)`。用 `AdapterRegistry.register` 注册适配器；可注入 `preamble`、`taskConcurrency`（默认 4）、`onEvent` 和 `onError`。启动时只为新发现的中断写系统提示。退出时先同步 `dispatch.close()`，再 `store.close()`。

`openDm(memberId)` 返回私聊记录，`sendMessage(conversationId, text)` 立即返回消息、运行、会话的 ID。`startWork({memberId, conversationId, title, goal})` 另建目录并投递目标。`finishWork(id)` 在正在执行的轮次中登记完成意图并返回当前工作项，轮末释放原生会话成功后更新为 done。空闲时直接收尾，失败保留可重试状态。

`subscribe` 返回退订函数，发出 message.created、message.delta、run.started、run.ended、run.event、member.status、work.updated。审批细节只随实时事件传出。T-010 可取 `memberStatus`、`store.dispatch.listMemberIds/listWork/recentWorkEvents`、`store.workItems.get` 与 `store.messages.dmBefore/dmAfter` 组装只读命令；私聊分页排除工作项内部消息。

## 修正与验证

独立评审发现并发收尾可能重复休眠，休眠失败会让工作与会话状态分离。现已合并同一工作的并发请求，成功后同一事务更新工作和会话。另一个回归验证了不支持中断的适配器拒绝忙时休眠后，关库仍立即返回，流退出时成功释放原生会话。完整回归还发现私聊专用查询提前准备影响原分页测试，已改为首次使用才准备语句。Windows 上运行 `pnpm check` 与 `pnpm test`，66 项通过，含本卡 20 项。逐条证据见任务卡，测试使用假适配器和真实临时 SQLite。

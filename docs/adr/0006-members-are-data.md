# ADR-0006 成员是数据，创建走统一接口

- 状态：已采纳
- 日期：2026-11-15
- 对应决定：`DECISIONS.md` D-013

## 背景

老板不希望成员名单写死。成员应当可以随时创建，也可以让成员自己帮忙创建。
这带来冷启动问题：一个成员都没有时，找谁创建第一位成员。

## 决定

- 成员是数据库里的记录加一个成员目录，不是代码里的常量。
- 创建、修改、停用成员只有一个入口：内核的成员接口。界面表单和成员工具都调用它。
- 内置一位成员「人事」，首次启动时自动创建，负责帮老板创建和管理其他成员。
  它和别的成员用同一套接口和工具，区别只在人设。
- 由成员发起的创建和修改不直接生效，先生成待老板确认的请求。（假设，见 Q-006）

## 放弃的方案

| 方案 | 放弃的原因 |
| --- | --- |
| 预置一套固定成员 | 老板明确不要 |
| 只能通过界面表单创建 | 失去"让成员帮我招人"的体验；冷启动时老板要自己填所有字段 |
| 成员可以不经确认直接创建成员 | 每位成员都占资源并能接触老板的工作，创建应当由老板知情 |

## 后果

- 「人事」的大脑用首次启动时检测到的可用 harness。一个都没检测到时，引导老板先完成 harness 的
  安装或登录，此时只能用界面表单。
- 需要一个内核提供的成员工具服务（MCP），第 1 期就要有。
- 「人事」不能被停用，但可以改名和改人设。

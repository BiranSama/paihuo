# ADR-0007 注意力规则与先观察再放权

- 状态：已采纳
- 日期：2026-11-15
- 对应决定：`DECISIONS.md` D-005

## 背景

多个成员同时工作时，最容易被消耗的是老板的注意力。同时老板又希望成员能自己发现事情。
参照 DeepSeek Super-agent 的设计原则：尽量少占人的注意力，尽量多给价值。

## 决定

"这件事值不值得做"和"这个进展值不值得现在告诉老板"是两个分开的判断。

何时开口：

- 收到请求只确认一次，说明打算做什么。
- 干活时保持安静，过程写进工作记录，可展开查看。
- 只在三种情况主动找老板：有可用的结果、需要决定、做不下去。
- 提问一次只问一个具体问题。
- 例外：老板在群里参与讨论时，成员发言本身就是价值，不受"安静"约束。

主动性：

- 新的主动工作先进"只记录"模式：记下它本来会做什么，不真的做。
- 老板看记录觉得靠谱，再对这一类工作放开自动执行。
- 长期没有产出有用结果的例行工作，能一键暂停。

这些规则写进每位成员的人设前言，并由内核在界面层面落实（过程折叠、合并通知）。

## 放弃的方案

| 方案 | 放弃的原因 |
| --- | --- |
| 所有主动发现的事都起草方案等批准 | 每次都要老板点头，本身就在消耗注意力；也无法判断哪类工作值得自动化 |
| 一上来就全自动 | 没有观察期，出错代价高 |
| 成员始终只在结束时出现 | 抹掉了讨论和头脑风暴的价值 |

## 后果

- 第 1 期只落实"何时开口"和过程折叠。待决定事项在第 2 期，只记录模式在第 5 期。
- 需要记录"无效打扰"的次数，作为老板评估是否省注意力的依据。

# ADR-0001 自己写小内核，不分叉现成项目

- 状态：已采纳
- 日期：2026-11-15
- 对应决定：`DECISIONS.md` D-009

## 背景

社区已有多个相近项目。调研后最接近的是 Clowder AI（原生 CLI 直接当成员）和 Hermes Agent 的
Bot Mode（个人助手加群聊体验）。问题是：在它们之上二开，还是自己写。

## 决定

自己写一个只包含本项目概念模型的小内核。别人做好的设计照着做，小模块在许可允许时参考其实现。

## 放弃的方案

| 方案 | 放弃的原因 |
| --- | --- |
| 持续跟上游的 Clowder 分叉 | 每改一处核心，以后每次上游更新都要自己合并 |
| 一次性硬分叉 Clowder | 接手的是自己读不懂的代码：API 部分非测试 TypeScript 文件约 3,860 个、约 64 万行，调度核心单文件近七千行；其概念模型（猫、线程、接球、任务大厅）与本项目不同 |
| 以 Hermes Bot Mode 为底座 | 源码核查显示同一成员的执行被锁成串行；官方文档把对话中途的实时打断列为未来工作；原生 harness 作为成员尚无现成适配 |
| 以 OpenClaw 为底座 | 多 agent 群讨论为实验性功能；走 ACP 绑定的 harness 不进入这种群 |
| 以 DeepSeek Super-agent 原型为底座 | 只服务单个 GitHub 仓库，依赖 DeepSeek Harness |

## 后果

- 起步比二开慢，但每一行代码都读得懂、改得动。
- 需要自己实现调度、会话管理和持久化，这是第 1 期的主要工作量。
- 借用清单见 `docs/design.md` 第 9 节。借用代码时保留原许可与版权声明。
- Clowder 仍值得装来试用，作为第 2、3 期交互设计的参照。

## 依据

Clowder 的结论来自对 v0.14.1（提交 592f07ae）的静态阅读，没有运行验证。Hermes 的串行锁结论来自
外部调研报告的源码核查，本项目未独立核实。

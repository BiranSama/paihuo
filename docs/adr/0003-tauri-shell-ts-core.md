# ADR-0003 桌面外壳用 Tauri，内核用 TypeScript 独立服务

- 状态：已采纳
- 日期：2026-11-15
- 对应决定：`DECISIONS.md` D-010

## 背景

老板要的是像 Codex 客户端那样的独立桌面应用，不要浏览器里的网页；在意内存占用；
先 Windows，之后 Mac，手机最后。项目主要由 AI 编写。

## 决定

- 桌面外壳用 Tauri 2，界面用 React + TypeScript。
- 内核是独立的 TypeScript 本机服务，作为外壳的附带进程启动；界面只是它的客户端，
  通过本机 WebSocket 通信。
- 外壳里的 Rust 代码尽量薄：窗口、托盘、启动和守护内核、取系统路径。业务规则一律不写在 Rust 里。

## 放弃的方案

| 方案 | 放弃的原因 |
| --- | --- |
| Electron | 风险最低、生态最成熟，但自带浏览器内核，体积和内存最重；不支持手机 |
| 原生框架（如 Flutter） | 界面与内核是两种语言，要多维护一层通信；可借用的现成代码最少；没有换壳退路 |
| 本机网页界面 | 老板明确不喜欢 |
| 内核用 Rust 写进外壳 | 最省内存，但失去 TypeScript 生态里的 SDK，AI 迭代 Rust 也更慢 |

## 后果

- 多一门 Rust 和它在 Windows 上的构建工具链。
- Windows 用 WebView2，Mac 用系统自带的 WebKit，两边渲染有差异，上 Mac 时界面要单独测。
- 内核作为附带进程要一起打包，打包比 Electron 麻烦。T-001 要先把"外壳启动内核"跑通。
- 在 Windows 上，系统内核 WebView2 本身也基于 Chromium，内存优势没有宣传的那么大。
  真正的内存大头是成员进程和对话状态，靠 `docs/design.md` 第 7 节的内存约束控制。
- 退路：界面是 React + TypeScript，内核是独立服务。如果 Tauri 走不通，换成 Electron 只需重做外壳。
  触发换壳的条件：T-001 无法在 Windows 上稳定启动和守护内核，或上 Mac 时渲染差异的修补成本
  超过重做外壳。

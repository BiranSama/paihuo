# ADR-0002 一个身份，四种会话

- 状态：已采纳
- 日期：2026-11-15
- 对应决定：`DECISIONS.md` D-008

## 背景

harness 当成员时，要决定它的会话怎么分。需求里同时要求：成员有连续的身份和记忆；
同一成员能并行多项工作；能休眠后恢复；干活时仍能回话；私聊内容不漏进群。

## 决定

成员身份在会话之上。按场合开会话：私聊会话、群会话、任务会话、一次性调用。
连续性靠身份层（人设、长期记忆、工作日志）在会话启动时注入，不靠共用上下文。
内核维护"成员 + 场合 → 原生会话 ID"的对照表。详见 `docs/design.md` 第 4 节。

## 放弃的方案

| 方案 | 放弃的原因 |
| --- | --- |
| 每位成员只有一条会话 | 上下文迟早写满；私聊、群、任务混在一起，私下说的话会漏进群；同一时刻只能处理一件事，干活时没法回话，也无法并行 |
| 每条消息新开会话 | 没有连续性，每次都要重讲背景 |
| 多个成员共用一条会话、靠提示词扮演 | 没有独立的上下文和责任，不算员工 |

## 后果

- 需要一套写回机制：工作做完把结论写进工作日志，否则私聊会话不知道任务会话做了什么。
- 恢复失败时只能"接续背景"，必须如实告诉老板不是无损恢复。
- 同时活跃的会话数决定内存占用，需要上限和空闲休眠。
- Clowder 按"成员 + 线程"存会话链，方向一致，可作参考。

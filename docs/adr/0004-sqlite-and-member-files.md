# ADR-0004 存储用 SQLite 加成员文件目录

- 状态：已采纳（成员文件形式见 D-019，Q-003 已解决）
- 日期：2026-11-15

## 背景

需要持久化成员、会话对照表、消息、工作项和运行记录，并在重启后恢复。只有一个使用者，一台机器。

## 决定

- 结构化数据放一个 SQLite 文件。表结构见 `docs/design.md` 第 5 节，改动走迁移文件。
- 每位成员的人设、长期记忆、工作日志放在成员目录下的 Markdown 文件里。
- T-002 使用随固定 Node.js 24 运行时分发的 `node:sqlite`（`DatabaseSync`）。Windows x64 实测能通过内置驱动建库、迁移和强杀恢复。额外的原生绑定需要管理 Node ABI 对应的二进制，WASM 还需单独处理文件持久化。

## 放弃的方案

| 方案 | 放弃的原因 |
| --- | --- |
| Redis | 要额外安装和守护一个服务；Windows 上没有官方原生版本；自用不需要它的并发能力 |
| 只用文件（JSON / JSONL） | 分页、按会话查询、并发写入都要自己实现 |
| 记忆也全部进数据库 | 老板和成员都难以直接阅读和修改；Markdown 文件可以直接打开看、手工改、纳入备份 |

## 后果

- 在内核退出、数据库关闭后，可复制整个数据目录进行备份。
- 记忆文件可能被老板、成员和内核同时修改，需要约定：成员只追加工作日志；长期记忆的修改经内核写入。
- 成员的记忆和日志按 D-019 保存在本地 Markdown 文件，读写由成员模块管理。

# 派活 · 北极星宪章

> 这份文件几乎不改。它回答"为什么做"和"什么不做"。需求、设计、任务与它冲突时，以它为准；
> 要改它，必须由老板本人在 `DECISIONS.md` 里记一条决定。

## 北极星

**让一个人像带一支熟悉的小团队那样工作：事情持续推进，背景不用反复交代，注意力只花在值得花的地方。**

派活是老板一个人用的个人 Agent 团队。几位有固定身份和记忆的成员，既是个人助手，也是员工，
也是一个工作群。老板可以给方向、提目标、找灵感、验证想法，也可以随时亲自下场。

## 核心价值

1. **省注意力。** 尽量少占老板的注意力，尽量多给价值。每一条消息、每一个提问、每一个设置项
   都要值回它占用的注意力，否则删掉。
2. **成员有连续性。** 成员记得自己是谁、做过什么、和老板怎么配合。老板不需要每次重讲背景。
3. **老板随时能插手。** 任何时候都能改方向、接手一步、叫停。成员干活时也有人应答。
4. **成果留得下。** 讨论和工作最后要留下能继续用的东西：文档、文件、结论、待决定的事。
5. **诚实。** 草稿标明是草稿，失败如实报告，没验证的不说成验证过。

## 取舍原则

两件事冲突时，按下面的顺序选左边：

| 优先 | 让位 |
| --- | --- |
| 可靠地做好少数事 | 功能多 |
| 少打扰 | 显得勤快 |
| 借用别人做好的设计和模块 | 自己重新发明 |
| 保留各 harness 的原生能力 | 接口看起来整齐 |
| 老板自己用着顺手 | 对所有人通用 |
| 一个读得懂的小内核 | 一个功能齐全的大框架 |
| 先观察、再放权 | 一上来就全自动 |

## 永远不做的事

- 不做多租户、团队版、计费和权限体系。使用者只有老板一个人。
- 不在没有批准的情况下做对外有后果的事：发邮件、发帖、付款、删除工作区以外的东西。
- 不把私聊内容自动公开给群或其他成员。
- 不假装完成。做不到就说做不到。
- 不为了"看起来像一家公司"而增加会议、审批和流程。
- 不深度分叉任何现成项目。只借设计和小模块，保留许可与版权声明。
- 不上传使用数据。数据留在老板自己的机器上。

## 怎样算成功

不承诺百分比，只看老板自己的真实使用：

- 第二天遇到类似的事，老板愿意主动打开它。
- 重复讲背景、转发材料、追问进度这类机械协调明显减少。
- 成员之间交接不需要老板转述。
- 中途改方向、隔天继续，不增加返工。
- 日常维护花的时间没有抵消省下的时间。
- 成果质量没有因为"安静"或"快"而变差。

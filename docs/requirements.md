# 派活 · 需求文档

版本：v0.1（对应产品第 1 期）｜更新日期：2026-11-15

> 每个产品版本更新一次。这里写"做什么"，"怎么做"在 `docs/design.md`。
> 标了【假设】的内容还没有得到老板确认，对应条目在 `QUESTIONS.md`。

## 1. 一句话定位

派活是一个跑在自己电脑上的个人 Agent 团队：几位有固定身份和记忆的成员，可以私聊、进群讨论、
接任务、交付成果；成员的大脑可以是 Claude Code、Codex 这类 harness，也可以是自研 agent。

一句话介绍：**老板，派活吧。**

## 2. 目标用户

只有一个：老板本人。

- 同时用多个 AI 编码工具和助手，厌倦了在窗口之间复制粘贴、重讲背景。
- 工作不只是写代码，还包括调研、内容生产和日常事务。
- 先在 Windows 桌面使用，之后是 Mac，手机最后。

## 3. 核心场景

老板的角色随事情变化。系统靠老板说的话判断，不做成模式开关。普通聊天可以不产生任何任务；
老板说"按这个做"，才为需要持续执行的部分建立工作项。

| 老板此刻想要 | 成员怎么响应 | 留下什么 |
| --- | --- | --- |
| 找灵感 | 提不同方向，追问关键约束，允许没有结论 | 候选方向、待澄清的问题 |
| 判断可行性 | 核实事实和假设，给反例和最小验证办法 | 证据、风险、下一步实验 |
| 一起做 | 分工后继续接受补充，允许老板接手局部 | 可继续编辑的成果 |
| 交付目标 | 自行拆解协调，在授权范围内推进 | 结果、验证记录、待决定的事 |
| 长期关注 | 按约定条件检查变化 | 更新记录、必要提醒 |

五个贯穿场景（也是验收的骨架）：

- S1 **单独追问**：分别私聊两位成员，各自接着自己的工作背景回答。
- S2 **隔天继续**：关掉界面工作继续；重启后对话和任务还在。
- S3 **同时干两件事**：同一位成员并行两项任务，互不干扰。
- S4 **中途改方向**：成员干活时老板发修改指令，界面说明已生效还是排队，旧步骤不再继续。
- S5 **讨论转派工**：在群里从找灵感转到验证再到交付，责任人和材料延续。

## 4. 功能分档

"期"是产品阶段。v0.1 只交付第 1 期；其余各期在这里登记，是为了让第 1 期的设计不堵死后面的路。

### 第 1 期（v0.1，本版必须）

| 编号 | 功能 | 说明 |
| --- | --- | --- |
| F1-01 | 成员 | 有名字、职责、人设、对老板的称呼；是数据不是代码 |
| F1-02 | 创建和管理成员 | 通过界面创建、修改、停用；走内核统一接口 |
| F1-03 | 内置成员「人事」 | 首次启动就在，帮老板创建其他成员；它发起的创建要老板确认【假设】 |
| F1-04 | 私聊 | 老板和一位成员的长期对话 |
| F1-05 | 任务会话 | 重活放进独立会话和目录，私聊保持能回话 |
| F1-06 | 同一成员并行 | 同一成员可同时有多条任务会话 |
| F1-07 | 休眠与恢复 | 成员不干活时不留进程；再叫它时接着原来的对话 |
| F1-08 | Claude Code 适配 | 作为成员的大脑 |
| F1-09 | Codex 适配 | 作为成员的大脑 |
| F1-10 | 桌面应用 | 独立窗口；关窗口不等于停止后台 |
| F1-11 | 工作记录 | 工具调用等过程默认折叠，可展开 |

### 第 2 期：插话与工作视图

- 引导（把新消息送进正在进行的这一轮）和中断（停下后按新消息重来）。
- 待决定事项：成员向老板提一个具体问题，等待期间继续做不依赖它的部分。
- 工作视图：需要我决定、进行中、已有结果。

### 第 3 期：群聊

- 自由发言：被 @ 必答；没被 @ 的可以发言也可以"过"；同一时刻一人发言；老板的消息优先。
- 停止：全员"过"自然结束、僵局上交、目标达成、老板介入、预算上限暂停。【假设】
- 主持方式：无主持、成员主持、老板主持。
- 独立首轮：重要判断先各自提交结论，再公开交换。
- 可见范围：私聊默认不进群；一句话把结论带回群。

### 第 4 期：自研 agent 与一次性调用

- 自研 agent 作为与 harness 平级的成员。
- 成员把某个 harness 当工具调用一次，不带身份，不写记忆。

### 第 5 期：主动性

- 触发器：定时、文件变化、邮箱和日历轮询。
- 新的主动工作先进"只记录"模式，老板认可后再放开自动执行。

### 第 6 期：日常事务

- 邮件和日程的连接与授权；对外动作逐次审批。

### 第 7 期：其他入口

- Mac、手机或聊天软件桥接。

## 5. 验收标准（v0.1）

用一件真实的小工作走完下面每一条，并留下实际产物。

| 编号 | 标准 | 对应 |
| --- | --- | --- |
| A-01 | 能通过界面创建一位成员，指定职责、人设和大脑（Claude Code 或 Codex） | F1-01 F1-02 |
| A-02 | 首次启动时「人事」已存在；对它说"招一位做调研的同事"，确认后新成员出现在列表里 | F1-03 |
| A-03 | 分别私聊两位成员（一位 Claude Code、一位 Codex），各自记得本对话早先的内容 | F1-04 S1 |
| A-04 | 交给成员一件需要改文件的事，它在独立目录里完成；期间私聊仍能得到回复 | F1-05 |
| A-05 | 同一位成员同时进行两项任务，两边的文件和上下文不串 | F1-06 S3 |
| A-06 | 成员空闲一段时间后进程消失；再发消息，它接着原来的对话回答 | F1-07 |
| A-07 | 关闭窗口后正在进行的任务继续；彻底退出再启动，对话、任务和成员都还在 | F1-10 S2 |
| A-08 | 工具调用过程默认折叠，可展开查看 | F1-11 |
| A-09 | 空闲状态下（无成员在干活）应用自身的内存占用记录在案，并写进 `STATUS.md` | 约束 C-04 |

## 6. 本版不做

- 群聊、插话、待决定事项、工作视图（第 2、3 期）。
- 自研 agent、一次性调用（第 4 期）。
- 任何主动触发、邮件日程连接（第 5、6 期）。
- Mac 和手机（第 7 期）。Mac 上能跑是加分，不是验收项。
- 多用户、账号体系、云同步、插件市场。

## 7. 约束

| 编号 | 约束 |
| --- | --- |
| C-01 | 先支持 Windows 10/11 原生运行，不依赖 WSL、tmux 或往终端注入按键 |
| C-02 | 独立桌面应用，不是浏览器里的网页 |
| C-03 | 内核是独立的本机服务，界面只是它的客户端 |
| C-04 | 省内存：对话历史分页加载；休眠成员不留进程；日志不记录完整响应内容 |
| C-05 | 数据只存本机 |
| C-06 | 不绑定某一家模型。harness 优先使用老板已有的登录；但程序化驱动是否计入订阅额度、是否合规、费用多少，以各家现行条款和 T-015 的实测为准，不默认免费（Q-013） |
| C-09 | 用量可见、可限：每位成员有用量上限，界面能看到每位成员花了多少；到达上限时暂停并告诉老板，不自动转为付费调用 |
| C-07 | 保留各 harness 原生的取消、权限、事件和会话能力 |
| C-08 | 开源，MIT 许可；借用代码时保留原许可与版权声明 |

| Q-002 | 群聊停止条件按第 3 期所列五种机制 |

## 9. 术语表

| 术语 | 含义 |
| --- | --- |
| 老板 | 使用者本人。成员对他的默认称呼，可在设置里改 |
| 成员（员工） | 一个有固定身份的 agent：名字、职责、人设、长期记忆、工作日志 |
| 人事 | 内置成员，负责创建、修改、停用其他成员 |
| 大脑（运行时） | 驱动成员的程序：某个 harness 或自研 agent |
| harness | 现成的 agent 程序，如 Claude Code、Codex CLI，自带工具循环和会话 |
| 会话 | 成员在某个场合的一段上下文。分私聊会话、群会话、任务会话、一次性调用四种 |
| 原生会话 | harness 自己的会话，由它自己的会话 ID 标识 |
| 工作项 | 一件需要持续执行的事，有目标、责任人、状态和产物 |
| 产物 | 工作留下的文件或文档 |
| 待决定事项 | 成员提给老板的一个具体问题 |
| 休眠 | 关掉成员的进程，保留会话，可恢复 |
| 引导 / 中断 | 中途插话的两种方式：送进当前这一轮；或停下后按新消息重来 |
| 内核 | 派活的本机服务，管理成员、会话、消息、调度和存储 |
| 适配器 | 内核和某种大脑之间的连接件，实现统一的员工接口 |

## 要做的事

逐项验证并记录"能 / 不能 / 有条件地能"，每项附上最小的可运行样例和观察到的现象：

1. 启动：从 Node.js 程序里开一条新会话，指定工作目录，并注入一段前言（人设和记忆）。
   比较 SDK 和 CLI 流式模式两条路线，选一条并说明理由。
2. 流式输出：拿到增量文本、工具开始和结束的事件。
3. 会话 ID：拿到原生会话 ID 并保存。
4. 恢复：结束进程后，用保存的会话 ID 恢复，确认它记得之前的内容。
5. 并行：同一台机器上同时跑两条互不相干的会话，各用各的工作目录。
6. 中断：一轮进行中把它停下，确认进程和会话的状态。
7. 引导：一轮进行中再送一条消息，观察它是被并入当前这一轮、排到下一轮，还是不支持。
8. 权限：工具调用需要批准时，程序能否收到请求并回答；有哪些权限模式。
9. 长对话：上下文接近写满时会发生什么，压缩是自动的还是可控的。
10. 成员工具：能否让这条会话连接一个本机的 MCP 服务。
11. 登录与计费：使用老板已有的登录是否可行，程序化调用有没有额外限制。如实记录看到的提示。
12. 资源：一条空闲会话和一条工作中的会话各占多少内存；休眠（结束进程）后是否完全释放。

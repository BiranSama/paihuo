## 目标

内核有一个可靠的存储层：第 1 期需要的表都建好，改表只走迁移，重启后数据还在。

## 先读

- `docs/design.md` 第 5 节
- `docs/adr/0004-sqlite-and-member-files.md`

## 涉及的文件

- `packages/core/src/store/**`
- `packages/core/migrations/**`
- `packages/core` 的依赖声明；内置 SQLite API 的最低 Node.js 版本同步到根包声明与 README
- `packages/shared/src/**` 中与这些表对应的类型

## 不许碰的文件

- `apps/desktop/**`
- `packages/core/src/` 下除 `store` 以外的目录
- 所有 `docs/` 下的产品与设计文档

## 要做的事

1. 选定 SQLite 驱动。要求：Windows 上安装不需要额外的编译环境，或者有预编译包；同步或异步均可。
   在 PR 里说明选择和放弃的备选。
2. 实现迁移机制：按编号顺序执行，记录已执行的版本，失败时回滚该次迁移。
3. 写第一批迁移，建立 `docs/design.md` 5.1 节列出的全部第 1 期表。
4. 为每张表提供类型化的读写函数。业务规则不写在这一层。
5. 数据目录的位置由外壳传入，代码里不写死平台路径；提供一个测试用的临时目录选项。
6. 消息按 `seq` 分页查询的函数，向前和向后各一个。
7. 启动时把上次未结束的 `runs` 标记为 `unknown`。

## 验收标准

- [ ] 在空目录启动后数据库文件和全部表存在。验证：自动化测试。
- [ ] 重复启动不会重复执行迁移。验证：自动化测试。
- [ ] 故意写一个会失败的迁移，数据库保持在失败前的状态。验证：自动化测试。
- [ ] 分页查询在 1 万条消息下返回正确的页，且不把全部消息读进内存。验证：测试加代码审阅。
- [ ] `sessions` 的唯一约束生效：同一成员、同一场合（`kind` 与 `scope_id`）不会有两条未归档会话，休眠仍占用该场合，归档后可重新开会话。验证：自动化测试。
- [ ] 进程被强行结束后重启，已提交的数据都在。验证：操作一遍并记录。

## 安全与费用的边界

- 只用老板已登录的账号，不新建账号，不填付款信息，不购买任何额度。
- 每条测试会话只发很短的消息，单个 harness 的全部测试控制在 30 轮以内。开始前和结束后各记一次用量页面或命令显示的数字。
- 测试只在每次新建的临时目录里进行，不碰老板的其他项目。
- 权限一律用最严格的模式开始；某项测试需要放宽时，只对那条会话放宽，并在报告里写明。
- 不把会话内容、令牌、账号信息提交进仓库。报告里的会话 ID 打码。
- 跑之前先把要执行的命令清单给老板看，老板说可以再开始。

## 要做的事

对 Claude Code 和 Codex 各做一遍，每项记录"能 / 不能 / 有条件地能"、实际命令或代码、观察到的现象：

1. **路线**：Claude Code 比较 SDK 流式模式和 CLI 流式模式，Codex 比较 App Server 和一次性执行模式，各选一条并说明理由。
2. **启动与前言**：开一条新会话，指定工作目录，注入一段人设前言（例："你叫阿测，回答时先说你的名字"），确认生效。
3. **流式事件**：拿到增量文本、工具开始和结束的事件，能映射到 `AdapterEvent` 的哪几种。
4. **恢复**：记下会话 ID，告诉它一个暗号；结束进程；用会话 ID 恢复，问暗号。再用一个不存在的 ID 恢复，记录报错，看能否映射到 `native_session_lost`。
5. **中断**：让它做一件需要几十秒的事，中途中断。记录：中断后进程状态、这条会话能否继续用、已发生的文件改动是否保留。
6. **引导**：一轮进行中再送一条消息，看是并入这一轮、排到下一轮、还是不支持。
7. **并行**：同时开两条会话，各用各的目录，各做一件事，确认事件和文件不串。
8. **权限**：让它做一次需要批准的操作（例：在工作目录外写文件）。记录程序能否收到请求、能否代答、有哪些权限模式，以及哪种模式能实现 Q-014 的选项 A。
9. **成员工具**：让会话连接一个本机最小 MCP 服务（只提供一个返回固定文本的工具），确认能调用。
10. **计费与认证**：记录这次调用计入的是哪个额度（订阅的交互额度、程序化额度、API），依据是什么（用量页面、命令输出、官方条款原文链接）。找不到确切依据就写"无法确认"，不要推测。
11. **资源**：一条空闲会话、一条工作中的会话各占多少内存；结束进程后是否完全释放。
12. **压缩**：如果 30 轮内能观察到上下文压缩就记录；观察不到就写明，Q-004 留待以后。
